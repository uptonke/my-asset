# Private performance attribution v1.0
Run `sql/performance_attribution.sql` once in Supabase SQL Editor, then manually run Update Private Performance Attribution. The workflow reads the existing ledger and NAV, reconstructs dated holdings, and only publishes the separate performance_attribution JSONB column through a service-role-only RPC with a compare-and-set ledger/history check. A trigger invalidates the report whenever the underlying ledger or NAV changes. No GitHub JSON output, no change to ledger, weights, or approval. Existing portfolio_db RLS applies to reads; review it separately.

Actual portfolio P&L = ending NAV - starting NAV - recorded external flows. Per-ticker P&L uses historical Close (not dividend-adjusted), signed transaction cash flows and opening/closing holdings, split into native price, FX, interaction, and execution vs close. Asset class aggregates are based on the same rows. Corporate split ambiguity, missing or stale quotes, unrecorded dividends/fees, manual NAV marks, and other discrepancies remain explicit residual, not forced into attribution. Ledger dates assumed end-of-day; market calendar/timezone mismatch may matter. Windows use nearest earlier available NAV snapshot and show dates. No broker-certified realized cost-basis P&L.

Factor attribution uses seven-day actual NAV Modified Dietz intervals, computes TWD and USD returns independently (converting flows on their dates), US daily FF5+Momentum spreads compounded weekly, TW index converted to USD and BTC USD excess returns. OLS with HAC(4) requires at least 52 intervals and full rank. In-sample descriptive only; factor sources may lag NAV, missed weeks excluded, Carino links the latest contiguous covered periods without bridging gaps. USD contributions translated by (1+FX), FX and Dietz conversion bridge retained explicitly. No rolling out-of-sample beta yet.
